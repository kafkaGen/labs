# Vision: <project name>

**Status:** Exploring / Active / Paused / Done
**In one line:** <what this is>

## Problem

What is missing or broken, and for whom. What you do about it today instead. Why it is worth fixing now.

## Goal

What is true once this works. One to three sentences. Not the checks that prove it: those are the success criteria.

## Learning objectives

What you want to learn or get better at through this project, and what counts as having learned it. This is a second reason the project exists, and it is what breaks the tie when the fastest way to ship conflicts with the way you would learn more. Delete this section if the project is not a learning project.

## Users

Who this is for. "Me" is a real answer for a pet project; say it plainly. If there is more than one kind of user, name the one that matters most.

## Core use cases

The flows you will actually walk through, one sentence each: who does what, to get what. Two to five.

The capability boundary: what this can do, stated as what it does rather than how it is built. Do not restate the use cases above; list what they imply or leave out.
